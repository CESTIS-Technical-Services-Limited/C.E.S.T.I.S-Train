================================================================================
  C.E.S.T.I.S  —  OFFLINE SYSTEM
  The whole platform, on your own computer, with no internet.
================================================================================

This folder is a complete copy of the CESTIS system. It runs on one computer at
the Centre and serves every other device — laptops, tablets, phones — over your
own wifi or cable network. Nothing goes to the internet. Nothing needs it.


--------------------------------------------------------------------------------
  1.  STARTING IT
--------------------------------------------------------------------------------

Put this folder somewhere sensible on the computer that will act as the server
(the Coordinator's laptop or the office desktop). Then:

    Windows ....... double-click  START-WINDOWS.bat
    Mac ........... double-click  START-MAC.command
    Linux ......... double-click  START-LINUX.sh   (or: bash START-LINUX.sh)

A black window opens and prints something like:

    On THIS computer, open:
        https://localhost:8080/index.html

    On ANY OTHER device on the same network, open:
        https://192.168.1.24:8080/index.html

LEAVE THAT WINDOW OPEN. Closing it stops the system for everybody.

Note the https. It is not decoration: browsers only allow the camera and
microphone on an address they trust, so video classes need it. See section 2.

On a Mac the first double-click may be refused ("unidentified developer").
Right-click the file, choose Open, then Open again. Once only.


--------------------------------------------------------------------------------
  2.  OTHER DEVICES
--------------------------------------------------------------------------------

Every device must be on the SAME network as the server computer — the same wifi,
or plugged into the same router. No internet connection is needed on that
network; a router with no internet works perfectly.

On each device, open a browser and type the https://192.168... address the black
window printed. Bookmark it.

THE FIRST TIME, EXPECT A WARNING
The browser will say the connection is "not private", or show a red padlock.
Click Advanced, then Proceed / Continue / Visit this website. The device
remembers and never asks again.

That warning is not about your data being exposed. It means nobody famous
vouched for this server's certificate — nobody could, because a certificate
authority lives on the internet and there is none here, and no authority issues
certificates for a private address like 192.168.1.24 in any case. The server
makes its own on first run and keeps it in the "cert" folder. The connection is
encrypted either way.

If a device cannot reach it:
  - check it is on the same wifi, not a phone's mobile data;
  - the server computer's firewall may be blocking it. Allow Node.js, or allow
    port 8080, when the firewall asks;
  - the address changes if the router restarts. Read the new one off the black
    window. Ask whoever manages the router to reserve a fixed address for the
    server computer and the problem goes away for good. (When the address does
    change, the server makes a fresh certificate for it, so devices are asked to
    accept it once more.)


--------------------------------------------------------------------------------
  3.  WHERE THE DATA LIVES
--------------------------------------------------------------------------------

    Offline System / data /

Every part of the system saves there and reads from there — the LMS, Student
Progress, Transcripts, School Fees, the Cashbook, Payment Vouchers, Invoices,
Quotations, Purchase Orders, Virements, Payslips and the Time Clock. One file
each, plus CESTIS_ALL_DATA.json which holds the whole system's storage.

That last file is what makes this folder do the job Google Drive does online:
anything any page saves ends up here, not only the parts each page listed for
itself. Sign-in tokens, which Drive file a machine last used, who is signed in
on a given screen and display choices stay on their own computer on purpose —
copying those between machines causes problems rather than solving them.

Read that folder's own note for the full list.

BACK IT UP. Copy the "data" folder to a memory stick on a schedule somebody is
responsible for. It is the Centre's records, and it lives on one computer.

EVERY SAVE KEEPS THE PREVIOUS VERSION. Inside "data" there is a hidden folder
called ".history" with one folder per file, holding the last 40 versions of it,
named by date and time. If a file is ever damaged or a bad save gets through,
stop the server, copy the version you want from data/.history/<file>/ back over
data/<file>, and start the server again. (On Windows, turn on "Hidden items"
in File Explorer's View menu to see the folder.)

HOW SAVES ARE COMBINED. Several devices saving at once is normal in a class.
The server merges every save into what it already holds, by the same rules
every device uses: lists of records (trainees, exam results, attendance,
submissions, chat, announcements...) are combined record by record, so a save
from a device that holds fewer records — a trainee's PC after they sign out, a
tablet that has not caught up yet — never removes anybody else's. Records are
only ever removed by an actual deletion in the system, which every device then
honours. Who is signed in on a screen, and an exam half-way through, are never
shared between devices.


--------------------------------------------------------------------------------
  4.  WHAT WORKS OFFLINE, AND WHAT CANNOT
--------------------------------------------------------------------------------

WORKS, completely offline:
    Trainee enrolment, progress, attendance, assignments and exams
    Transcripts, grades, certificates and the certificate downloads
    School fees, the cashbook, invoices, quotations, purchase orders,
      payment vouchers, virements, payslips and the time clock
    Every user account, sign-in and role
    Video classes and LMS Chat calls between devices on this network
    Income & Expenditure statements, and the Board's (CMC) view of the books
    Sharing all of the above across the Centre's own network

DOES NOT WORK without internet, by nature:
    Google Drive sync — replaced by the data folder above, which does the same
      job on your own network
    Emailed one-time codes for password resets — an administrator resets
      passwords directly instead (Settings > Users > Reset Password)
    Qualification Plan / Curriculum documents, which are held in Google Drive.
      Copy the PDFs into this folder if you need them offline.
    MegaData (the migration tool): its pages are here, but it needs its
      online broker, so offline they simply stay in their normal mode.

Nothing else changes. The pages, the roles and the records are identical to the
online version — the pages in this folder are generated from the online ones
(see "FOR WHOEVER MAINTAINS THIS FOLDER" at the end).


--------------------------------------------------------------------------------
  5.  VIDEO CLASSES
--------------------------------------------------------------------------------

These work offline. Start a class the same way as always.

Two browsers cannot begin a call unaided — something has to carry the first few
messages between them so each learns how to be reached. Online that is done by
a public server, which is why video used to be the one part that stopped
without internet. The offline server now does it here, on your own network.

What to expect:
  - everyone must be on the SAME network as the server, as with everything else;
  - the picture and sound travel DIRECTLY between the two devices, not through
    the server, so the server computer does not slow down with more people;
  - the first time each device joins, the browser asks permission to use the
    camera and microphone. Say yes. If it was refused once, clear it in the
    browser's site settings for that address;
  - the class is limited by the devices themselves, not by this software. Small
    groups are comfortable; a large class on old tablets will not be.

To see who is currently connected, open ON THE SERVER COMPUTER ITSELF:
      https://localhost:8080/_cestis/rooms
(Other devices are refused that page: it lists every class's room code, and
the room code is all it takes to join a class.)

A device that went to sleep, or dropped off the wifi, in the middle of a class
is let go by the server after about a minute of silence, so its owner can
reload and start or rejoin the class again.

If a call will not connect:
  - check both devices are on the same wifi, not one on mobile data;
  - check the black window is still open;
  - reload both pages and try once more — the room is created fresh each time.

"Video is not available at this page address"
    The page was opened over http:// instead of https://, and no browser will
    give the camera or microphone to a page reached that way over a network.
    Check the address bar: it must be the https:// one the black window printed.
    If the black window itself says "VIDEO CLASSES - LIMITED", this computer has
    no "openssl" command to make a certificate with. macOS and Linux already
    have it; on Windows it comes with Git (https://git-scm.com). Install it once
    and start the server again. Everything except video works meanwhile.


--------------------------------------------------------------------------------
  6.  MOVING DATA BETWEEN OFFLINE AND ONLINE
--------------------------------------------------------------------------------

The files in the data folder are the same format the online version keeps in
Google Drive. A data folder copied off this machine can be read by the online
system, and a Drive backup can be dropped in here.

Do it one way at a time. If the Centre works offline for a week and online at
the same time, both sides will have edits and somebody has to decide which
stands.


--------------------------------------------------------------------------------
  7.  WHO CAN SEE THE RECORDS — PLEASE READ
--------------------------------------------------------------------------------

Be clear about what protects the Centre's records on this network, and what
does not.

WHAT IS PROTECTED
  - Other websites. A web page open in somebody's browser cannot read or change
    the records: every request to the records must carry the server's access
    token, and browsers do not let other websites read it.
  - The records folder, the server's private key and the "User Login" folder
    are never served as files.
  - Saves cannot take records away (section 3), and the last 40 versions of
    every file are kept, so damage can be undone.

WHAT IS NOT PROTECTED
  - A person on the Centre's network who can open the system. Any device that
    can load the pages can obtain the access token the same way the pages do,
    and with some technical knowledge read the whole records store — including
    every account's password hash and two-step secret, payslips, and exam
    answer keys — or send it changes. A trainee's device that opens the system
    also holds a copy of the whole store in its browser storage.
    Proper per-person sign-in on the server (so each device receives only what
    its user may see) is not built yet.

WHAT TO DO ABOUT IT
  - Run the system on a network that only Centre devices join. Keep the wifi
    password away from personal phones and visitors; if trainees must use
    their own devices, give them a separate guest network that cannot reach
    the server computer, and use Centre-owned devices for exams.
  - Use strong passwords for every staff and administrator account (a weak
    password's hash can be guessed offline).
  - Treat the server computer as the Centre's safe: lock it, and do not share
    the "Offline System" folder, the "cert" folder or copies of "data".

The access token is kept in the "cert" folder, so restarting the server does
not interrupt pages that are already open. To change it (for example after a
staff member leaves), stop the server, delete cert/lan-token, and start it
again; open pages pick up the new one by themselves.


--------------------------------------------------------------------------------
  8.  IF SOMETHING IS WRONG
--------------------------------------------------------------------------------

"Port 8080 is already being used"
    Something else on the computer has that port. Start it on another one:
        node cestis-offline-server.js 8090
    and use :8090 in the address on every device.

"Node.js was not found" / "too old"
    The system needs Node.js 14 or newer. On a computer that has internet,
    download the "LTS" installer from https://nodejs.org, copy it onto a memory
    stick, and run it on the server computer. After that this folder never
    needs the internet again. (The package lists of some older Linux versions
    offer a Node.js that is too old; use the one from nodejs.org.)
    There is deliberately no fallback any more: the old Python fallback shared
    nothing between devices and handed the records folder and the private key
    to anyone on the network.

"Not reaching the Centre's server" (a red bar at the bottom of a page)
    That device's saves are not reaching the server, so its work is only on
    that device for now. Check the black window is still open on the server
    computer and the device is on the same network. The bar goes away by
    itself at the next successful save; reload the page if it asks you to.

A page is blank
    Refresh once. If it stays blank, stop the server window and start it again.

Somebody's work is missing
    Check the data folder has the file for that part of the system, and that
    their device is pointed at the server's address rather than a copy of the
    pages opened straight off a memory stick.

  FOR WHOEVER MAINTAINS THIS FOLDER

The pages and scripts in this folder are GENERATED from the online build by
tools/build-offline.js in the main repository — do not edit them here; edit
the online file and run  npm run build:offline  (the test suite fails until
you do). Only these belong to this folder alone and are edited here:
    cestis-offline-server.js, cestis-offline-signalling.js,
    cestis-offline-cert.js, cestis-offline-store.js,
    START-WINDOWS.bat, START-MAC.command, START-LINUX.sh,
    READ ME FIRST.txt, data/READ ME - THIS IS THE CENTRE'S DATA.txt,
    package.json, .gitignore and the tests/ folder.

# Residual risks — what can still go wrong, honestly

Spec §9 asks for "a list of residual risks — things that could still go wrong and what the
mitigation would be." These are the ones that remain AFTER everything built and tested on this
branch. None is hidden behind a green suite; each names its mitigation and its owner.

| # | Risk | Why it remains | Mitigation | Owner |
|---|---|---|---|---|
| R1 | **The Apps Script broker is untested against live Apps Script/Drive.** The glue (`Code.gs`) follows documented APIs but has never run in the real runtime; the promise-draining loop is the named likely adjustment. | This environment has no Google access (spec 5.3). | README-DEPLOY smoke tests are step one of deployment; nothing depends on the broker until they pass. Gate 7 (Drive round-trip) re-runs before cutover. | Operator |
| R2 | **Apps Script quotas and cold starts.** Free-tier web apps have daily quotas and multi-second cold starts; a term-opening payment rush is the worst case. | Accepted consequence of D1 (strictly zero-cost). | Writes are asynchronous behind the acknowledged-write contract — the clerk's UI never waits on the broker; the outbox drains when the broker answers. The unsynced counter makes backlog visible. If quotas bite in practice, batching intervals are tunable per device. | Client (accepts), operator (monitors) |
| R3 | **The shared-secret HMAC is a known weakness.** Anyone with the secret can write; the URL is public ("Anyone with the link"). | Accepted in the Section 0 verdict under D1 — no paid auth infrastructure. | Secret lives only in Script Properties + each device's local meta (never the repo, never exports); rotation is a one-page procedure (update Script Properties, re-enter on devices via MegaData-Admin); every event carries actor/device provenance so misuse is attributable after the fact. | Client |
| R4 | **Git history still contains the scrubbed PII and the old default credentials.** The working tree is clean (D8), but history rewrites require coordination. | Rewriting public history invalidates clones; needs a scheduled client action. | Coordinated `git filter-repo` rewrite + force-push at a client-chosen time; published default passwords/PIN must be rotated regardless (D8 lists them); TRN/NIS treated as exposed. | Client, scheduled |
| R5 | **Legacy Drive sync still runs during shadow.** Until cutover, the old page-cloud channel and the MegaData channel coexist; the old channel can still resurrect stale copies on devices that never open a bridged page. | Deliberate — rollback safety demands the legacy channel stay intact until sign-off. | Bridges re-converge on every tick (deterministic ids make resurrection harmless to the canon); per-page comparators surface any residue; cutover retires the legacy channel per docs/04 §9. | Automatic + operator review |
| R6 | **Duplicate human-facing numbers exist in legacy history.** Each device seeded its own invoice/receipt series and deleting the newest document frees its number. | Historical fact; renumbering history is forbidden (numbers are on paper in clients' hands). | `__findocReconcile()` reports every duplicate for human annotation; broker-issued numbers take over at cutover, making new duplicates impossible. | Operator (review), broker (future) |
| R7 | **Payslip screen staleness.** The payslip page holds its data in a closure with no reloader, so remote changes reach its STORAGE immediately but its screen only on next open. | Fixing it would mean editing legacy inline code — out of contract. | Documented in the glue; the wrap-after-save re-mirror guarantees storage cannot be permanently clobbered; screen staleness is bounded by a page reload. | Accepted |
| R8 | **Attendance day-grids and grade semantics are documents, not yet semantic events.** attendance.marked / assessment events exist in the registry but bulk elevation of imported grids is a reviewed step, not automatic. | Elevation changes meaning; doing it silently would violate the no-guessing rule. | Named deferred step (docs/04); Tier-B documents are lossless in the meantime, so elevation later loses nothing. | Next phase, reviewed |
| R9 | **The Offline System fork drifts.** `Offline System/` duplicates the pages; bridges landed only in the root tree. | Fork unification is its own project (docs/00 divergence register). | The offline server can point at the same broker endpoints later; until then the fork stays legacy and its exports import via the same extractors (identical shapes). | Next phase |
| R10 | **Storage eviction on shared machines.** IndexedDB can be evicted by the browser under pressure despite `navigator.storage.persist()`. | Browser behaviour outside our control. | Everything local is reconstructible from the broker log (wipe → pull → fold); the unsynced counter shows the only truly at-risk writes; persist() is requested on every page. | Automatic |
| R11 | **Objmap collections born only in bootstrap sync one-way until touched.** Voucher overrides / chat profiles / cert templates imported by the migration lack the `__k` rider, so a fresh device cannot reconstruct their map slot until some device touches them. | The legacy map shapes don't carry their own keys. | Documented in each glue; first local edit joins the doc fully; legacy page-cloud still syncs the raw maps meanwhile. | Accepted, self-healing |
| R12 | **One human, one queue.** Adjudication decisions are one keystroke and permanent (audited, but permanent in effect for merges). | Throughput design; an undo flow was out of scope. | Merges keep both records in history (`person.merged` evidence + fold `mergedInto`); a wrong merge is recoverable by a compensating correction with the audit trail intact — but it is manual. Defer liberally when unsure. | Adjudicator practice |

**Standing rule:** every PASS in `docs/03-VERIFICATION.md` re-runs at cutover against live
data; this list is reviewed at the same time and anything newly discovered joins it rather
than being absorbed silently.
